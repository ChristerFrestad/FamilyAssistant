# Meal planning picker — recipe selection on Meals screen

**Dato:** 2026-05-02
**Branch:** `feat/meal-planning-picker`
**Type:** Feature (frontend-only)
**Driver:** Manuell test-blocker for Sprint 6 finalize (PR #88).
"Planlegg middag"-knappen var ren placeholder fra Fase 2C; pilot
trenger faktisk plan-flyt for at smart-coupling skal være meningsfull.

---

## Reisen

### 1. Plan på tom dag

1.1. Bruker åpner Måltider-skjermen, navigerer til en dag uten recipe.
1.2. MealHero viser empty-state med "Planlegg middag"-knapp.
1.3. Bruker trykker → `RecipePickerDialog` åpnes.
1.4. Dialogen henter `GET /api/recipes` (alle 36 seed-oppskrifter +
     evt. importerte).
1.5. Bruker bruker søke-felt eller kategori-filter (rask / comfort /
     helg) for å snevre inn.
   1.5.1. Søk er prefiks- og substreng-match på `recipe.name`.
   1.5.2. Kategori-filter er multivalgt (alle/none/én/to/tre).
1.6. Dialogen viser per recipe: navn, kategori-badge, prep-time,
     allergi-flagg hvis `hiddenByAllergy` eller `shownWithDislikeWarning`.
1.7. Bruker trykker "Velg" på en rad.
   1.7.1. `swapMeal(weekYear, dayOfWeek, recipeId)` kalles
          (eksisterende `PUT /api/meals/swap` endepunkt).
   1.7.2. Backend setter recipe via `INSERT ... ON CONFLICT DO UPDATE`
          (samme funksjonalitet som "bytt").
   1.7.3. Hvis ukens måltider blir komplette og auto-shopping er
          aktivert, autogenereres handleliste — backend håndterer
          dette transparent.
1.8. Dialog lukker, MealHero re-renderer med valgt recipe.

### 2. Bytt eksisterende recipe

2.1. MealHero viser hero med recipe + "Bytt middag"-knapp.
2.2. Bruker trykker → SAMME `RecipePickerDialog` åpnes (gjenbruk).
2.3. Bruker velger ny recipe.
2.4. `swapMeal` overskriver recipe via `INSERT ... ON CONFLICT DO UPDATE`.
2.5. Dialog lukker, hero oppdateres.

### 3. Plan via WeekList "+ Legg til middag"

3.1. WeekList rendrer "+ Legg til middag"-rad for tomme dager.
3.2. Klikk åpner picker for den dagen (samme mønster som hero).

## Edge-cases (15+)

1. Tom recipe-liste (nybygg-state) — picker viser "no recipes"-empty-
   state med oppfordring om å importere.
2. Søk gir 0 treff — picker viser "no results for {query}".
3. Recipe blokkert av allergi (hiddenByAllergy) — vises grået ut + flag,
   "Velg" disabled.
4. Recipe blokkert av diet (hiddenByDiet) — vises grået ut + flag,
   "Velg" disabled.
5. Recipe med dislike-warning (shownWithDislikeWarning) — vises med
   gul flagg, "Velg" enabled.
6. swapMeal-call feiler (nettverk) — toast/inline error, dialog
   forblir åpen så bruker kan retry.
7. Bruker velger samme recipe som er der allerede — backend
   ON CONFLICT DO UPDATE skriver samme verdi, idempotent.
8. Bytt mellom kategori-filter mens søk er aktivt — kombineres med AND.
9. Svært lang recipe-navn — truncate med ellipsis.
10. Recipe uten prepTime — vis kun navn + kategori-badge.
11. Recipe med `status='cooked'` på samme slot — bytt nullstiller status
    til 'planned' (matcher backend setRecipe-default).
12. Modal lukkes via Escape eller backdrop — ingen API-kall, ingen
    state-endring.
13. Picker åpnet for én slot → bruker veksler dag i strip mens picker
    er åpen — vi lukker picker ved dag-bytte for å unngå skjult
    state-mismatch.
14. Recipes-fetch laster fortsatt ved velg → vi disable "Velg"-knapper
    til lista er på plass.
15. To raske klikk på "Velg" — disable mens swap-call er in-flight,
    re-enable etter response.
16. Backend-respons inkluderer `autogeneratedShoppingList` — vi
    surfacer det som status-toast hvis truthy (sjeldent).
17. Network race: bruker bytter dag og velger raskt en annen recipe —
    vi binder pickerens dayOfWeek til den dagen som var aktiv da picker
    ble åpnet, ikke den som er aktiv nå.
18. Modal-trap-fokus håndteres av eksisterende Modal-komponent (samme
    som UseDialog).

## Beslutninger

**BESLUTNING 1:** Kategori-filter — multivalgt eller single-valgt?
- **ANBEFALING:** Multi-select via toggle-pills (alle av default → vis
  alle; én eller flere → vis kun de).
- **HVORFOR:** "Quick + Comfort" er et naturlig søk når du har 30
  minutter; én-til-én ville blokkere. Pills-mønsteret er allerede etabl-
  ert i Shopping-filteret.
- **ALTERNATIVER:** Single-valgt dropdown — lavere fleksibilitet.
- **KONSEKVENS:** Begrenset filter-fleksibilitet hvis single-valgt.

**BESLUTNING 2:** Allergi/diet-blokkerte oppskrifter — skjul eller vis grayed?
- **ANBEFALING:** Vis grayed med flag og disable "Velg"-knapp.
- **HVORFOR:** Skjuling skaper en "hvor ble den av?"-mysterium. Visning
  forklarer hvorfor den er utilgjengelig og lar bruker forstå filteret.
  WCAG-flytene fra Fase 3A støtter denne approach (synlig kontekst).
- **ALTERNATIVER:** Skjul helt — usynlig regel, frustrerende UX.
- **KONSEKVENS:** Flat liste vs. kategorisk skjul.

**BESLUTNING 3:** Picker for plan vs swap — én komponent eller to?
- **ANBEFALING:** Én delt komponent. Forskjellen er bare kontekst-tekst
  ("Planlegg middag" vs "Bytt middag" i title).
- **HVORFOR:** Underliggende API-kall er identisk
  (`PUT /api/meals/swap`). Duplisering uten gevinst.
- **ALTERNATIVER:** To komponenter — vedlikehold-arv.
- **KONSEKVENS:** Mer kode å vedlikeholde.

**BESLUTNING 4:** Vise valgt recipe inline (preview) eller bare velg-knapp?
- **ANBEFALING:** Bare velg-knapp + minimal info-rad (navn, badge,
  prep-time, evt. ingredient-count). Ikke åpne separat preview.
- **HVORFOR:** Pilot-MVP-prinsipp: redusér klikk og context switching.
  Detaljert preview kan komme post-pilot.
- **ALTERNATIVER:** Ekspanderbar rad — adds complexity.
- **KONSEKVENS:** Bruker må klikke "Velg" for å se ingredienser i
  hero-card etterpå — akseptabelt.

**BESLUTNING 5:** Rydde opp placeholder-tekstene?
- **ANBEFALING:** Slett `meals.placeholders.planStatus` og
  `meals.placeholders.swapStatus` fra både no- og en-bundles, og
  fjern `onPlaceholderAction('swap'|'plan')`-callback-grenen fra
  MealHero.
- **HVORFOR:** Når funksjonaliteten er på plass, er placeholderne
  teknisk gjeld. Bedre å fjerne dem nå enn senere.
- **ALTERNATIVER:** La være, fjernes senere — DEL 7.7-debt.
- **KONSEKVENS:** Liten refactor i Meals.tsx-state. Rydding av callbacks
  som ikke trenger å eksistere lenger.
